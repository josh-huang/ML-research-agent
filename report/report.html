01 · Problem & approach

Score and autonomy pull against each other

The competition weights the metric (35%) and the agent — autonomy (20%), innovation (20%), feasibility (15%). A hand-tuned model wins the score but proves nothing about autonomy; a pure autonomous agent risks a weak score. This project takes both ends at once.

The task. Within-user ranking over logged impressions (no full-library retrieval). Label: long_view ∈ {0,1}. Metric: primary = mean(GAUC, nDCG@5), scored by the official evaluate.py — imported, never modified. Convergence: ε = 0.002 over N = 3 rounds. Oracle ceiling: 0.8645.

The approach — two layers. A hand-built, verified-strong floor first (FM → DeepFM → DIN, side features, aux losses), so the score never depends on the agent getting lucky. Then the agent runs the full closed loop on its own: reproduce the baseline, read its own EDA, propose, train, evaluate, reflect, converge — zero interventions.

The floor is injected as prior knowledge, but the agent is not allowed to blindly copy it — every turn must cite EDA evidence for a falsifiable hypothesis. In the run below the agent independently re-derived the same plateau the floor found, which is the point: it proves the autonomy claim rather than asserting it.

The run’s most important finding: seed noise, calibrated

Re-running the identical best config across seeds 0/1/2 gives valid primary 0.6053 / 0.6045 / 0.6049 (mean 0.6049, std ≈ 0.0003, range 0.0008) while test is far more stable: 0.5988 / 0.5988 / 0.5990 (std ≈ 0.0001).

Two consequences: test is the trustworthy generalization signal, while valid carries real ±0.0004–0.0008 jitter; and single-seed valid deltas below ~0.001 are indistinguishable from noise. That retroactively re-reads every “definitive” flat verdict as noise-floor-consistent, and every trustworthy signal (DIN +0.003, videoside +0.002, userside harm, BPR/listwise −0.002…−0.004) as the only effects that clear the floor. This is a reusable discipline the agent discovered and codified into its own playbook.

06 · Limitations & next

The agent’s value is ruling out dead ends

The honest headline is that the achievable gain is small (+0.0042): the user_id × video_id interaction and the binary label already capture the ranking signal, and every “rich” direction fights the binary metric. The agent’s value here is not discovering a +0.03 trick that doesn’t exist — it’s cheaply and reproducibly ruling out the plausible dead ends with a verifiable trail.

Its own EDA and playbook name the two genuinely unwired signal sources that sit outside the current config-only action space — the next thing to build:

1 · True sequential history density (hist_len / time_since_last, rank-relevance up to 0.850–0.894) — needs a new feature exposed to the model.

2 · Duration-aware negative-sampling reweighting — needs a harness-level change to the sampling/loss pipeline.

Both require code beyond config flags — which is exactly why the agent correctly stopped grid-searching and reported the plateau.

07 · Reproduce

Run it yourself

# deps
pip install torch numpy pandas anthropic python-dotenv

# data (KuaiRand-Pure) — see the official README
#   wget https://zenodo.org/records/10439422/files/KuaiRand-Pure.tar.gz && tar xzf ...

# put your Anthropic key in .env (ANTHROPIC_API_KEY=sk-...)

# reproduce the baseline & our model
python -m models.train --model fm --loss bce        # valid ~0.6020
python submission/make_submission.py                # DIN -> submission/final.csv

# run the autonomous agent (reproduces baseline, then iterates to convergence)
python -m agent.main --fresh --max_iters 10

The per-iteration log is in run_logs/run_log.jsonl; best-so-far state in run_logs/state.json; a live dashboard via streamlit run dashboard/app.py.

Pinned at commit ec5cd5a — the agent mutates config only, never code, so the commit plus each run-log action field give a fully reproducible trace.
