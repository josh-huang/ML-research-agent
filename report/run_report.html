  1. iter 4 Video side-information helps on top of DIN+CWM: adding use_videoside=true (video_type/music_type categoricals + 6 continuous item-quality features including duration, play_progress, engagement rates) to the best DIN+CWM anchor lifted valid primary from 0.6044 to 0.6053 (+0.0009 measured on primary=mean(GAUC,nDCG@5), GAUC 0.6726/nDCG@5 0.5379), a new best. This confirms item-side linear terms are rank-relevant in within-user ranking (candidates share a user context, so item features shift relative scores) and are NOT fully captured through the video_id embedding—the continuous duration/quality features add direct watch-time-correlate signal (corr(play_time,long_view)=0.634) that ID embeddings compress away. Direction forward: combine use_videoside with a sweep of CWM aux_weight (0.05–0.2) on this anchor, and consider use_userside since its categorical interactions with item fields become activatable now that item features are present.
  2. iter 3 The two independent gains STACK additively: DIN base (k=32, lr=3e-4, drop=0.2) + CWM censored watch-time aux (aux_weight=0.1) lifted valid primary to 0.6044, the new best, beating both DIN alone (~0.604) and DeepFM+CWM (0.6034). This confirms the CWM aux (one-sided full-watch signal) lives in a different subspace from DIN's target attention on user history, so their gains compound on the BCE main head. Keep this DIN+CWM combo as the anchor; next sweep aux_weight around 0.1 (0.05–0.2) and optionally add video-side features on top, since the item-quality linear terms (play_progress, engagement rates) are rank-relevant and haven't been tested yet.

Direction: sweep aux_weight around 0.1 and stack on the best DIN anchor (din bce + cwm aux) — the plateau is breakable.
